# 구조와 실행 흐름

## 구성

| 경로 | 책임 |
| --- | --- |
| `scripts/setup.ps1` | 준비 상태 확인, 로컬 실행 파일과 화면 배치 등록 |
| `windows/common.ps1` | 설정·자격증명·실행 상태와 프로세스 소유권 검사 |
| `windows/start.ps1` | 중복 실행 방지, 비밀번호 생성, 감시 프로세스 실행 |
| `windows/run-stream.ps1` | 화면 검증 후 Voxl 실행, 토폴로지 변경 감시 |
| `windows/stop.ps1` | PID·파일 경로·시작 시각을 검증하고 소유 서버 종료 |
| `windows/status.ps1` | 화면 정체성, 인증 401/200, PNG 크기 검증 |
| `windows/virtual-display/monitor-tools.ps1` | GDI·DXGI·SetupAPI 네이티브 화면 검사 |
| `windows/control-panel/` | Tkinter GUI, 비동기 요청 모델, PowerShell 브리지 |

## 화면 선택

Voxl v0.3.3은 유효하지 않은 화면 인덱스를 받으면 실제 화면으로 되돌아갈 수 있습니다. 따라서 `--display=1` 인수만으로 가상 화면 선택이 보장되지는 않습니다. 설정 시 저장한 실제 모니터와 현재 장치의 식별자·좌표·크기·주 화면 여부를 비교하고, 가상 디스플레이 장치가 정상 동작하는지, GDI와 DXGI가 같은 가상 화면을 가리키는지 확인합니다. 화면이 사라지거나 대상이 바뀌면 감시 프로세스가 자신이 실행한 Voxl을 종료합니다. 2초 주기 검사이므로 변경 감지가 즉시 이루어지는 것은 아닙니다.

등록은 기존 배치를 읽어 저장합니다. 드라이버 설치·삭제, 실제 모니터 해상도 변경, 가상 모니터 자동 활성화는 수행하지 않습니다. 기존 등록은 덮어쓰지 않습니다. 화면 배치를 의도적으로 변경한 경우 서버를 끄고 [재등록 절차](TROUBLESHOOTING.md#배치실행-파일-다시-등록)를 따릅니다.

## 서버 생명주기

`start.ps1`은 뮤텍스로 동시 시작을 직렬화하고, 포트가 다른 프로세스에 점유되어 있으면 중단합니다. 설정한 Voxl 실행 파일의 SHA-256을 검사한 뒤 숨김 PowerShell 감시 프로세스를 실행합니다. 비밀번호는 `VOXL_PASSWORD` 환경변수로 자식에 전달합니다. Voxl의 시작 출력에는 인증 토큰이 포함될 수 있으므로 표준 출력과 오류는 저장하지 않고 버립니다.

`stream-state.json`에는 PID·시작 시각·실행 경로·화면 대상을 기록합니다. 종료 시 PID만 믿지 않고 현재 프로세스와 다시 대조합니다. 파일이 없거나 소유권이 맞지 않는 다른 서버를 채택하거나 종료하지 않습니다. 포트 번호가 같은 다른 프로그램도 건드리지 않습니다.

GUI를 닫는 것은 Tk 창만 닫습니다. 서버는 감시 프로세스와 함께 유지됩니다. 서버를 끄면 감시 프로세스는 자식 종료를 확인하고 끝납니다. 자동 시작 서비스는 등록하지 않습니다.

## GUI 요청 처리

Tk 위젯은 메인 스레드에서만 수정합니다. 작업 스레드는 PowerShell 결과를 큐로 전달하며, 주기적 상태 조회는 약 6초 간격입니다. 켜기·끄기가 진행 중이면 충돌하는 조작을 막습니다. 요청 세대 번호로 오래된 상태 조회가 새 조작 결과를 덮지 못하게 합니다.

결과는 고유한 임시 JSON 파일에 닫힌 상태로 기록하고 GUI가 읽은 뒤 삭제합니다. 표준 출력 파이프로 결과를 받으면 장기 실행 감시 프로세스가 핸들을 상속해 부모 종료 후에도 EOF가 오지 않을 수 있습니다. 파일 전달 방식은 이 정지 문제를 피합니다. 결과와 오류는 정해진 상태 코드만 포함합니다.
