# 검증 범위

## 자동 검증

`pwsh -NoProfile -File scripts/verify.ps1`은 다음을 검사합니다.

- 모든 PowerShell 파일의 구문 분석
- 서버 상태 응답·오류 코드·오래된 요청 무시·동시 조작 방지
- 실제 Tk 창에 모의 서버를 연결한 켜기·끄기·열기·복사·닫기 동작
- 장기 실행 자식 프로세스가 출력 핸들을 상속해도 GUI 요청이 끝나는 회귀 사례
- 임시 폴더에서 바로가기 생성·멱등성·다른 바로가기 덮어쓰기 거부
- 로컬 상태·실행 파일·비밀 키 패턴이 소스 배포 목록에 들어가지 않는지 확인
- 격리된 런타임 계약 테스트

GitHub Actions는 Windows와 Python 3.13에서 같은 명령을 실행합니다. CI에는 실제 가상 디스플레이가 없으므로 드라이버·GPU·영상·원격 입력 통합 검증을 대신하지 않습니다.

## 실제 PC에서 확인한 기반 동작

2026-11-05, Windows 11 x64에서 Python 3.13, PowerShell 7, Voxl v0.3.3, Virtual Display Driver 25.7.23 조합으로 원본 설치의 다음 동작을 확인했습니다.

- 실제 화면과 구분되는 1920×1080 가상 화면 송출
- 인증 전 401, 인증 후 200과 PNG 화면 크기 확인
- GUI의 실제 서버 켜기·끄기, 실제 클립보드 비밀번호 복사
- GUI 창을 닫은 뒤에도 서버 유지
- 원본 환경을 수정하지 않는 패키지의 읽기 전용 설치 사전 검사
- 임시 복사본에서 실제 로컬 등록 파일 3개 생성과 중복 등록 거부; 자격증명 생성·서버 실행·화면 배치 변경 없음

공개 패키지 GUI는 별도 모의 서버로 회귀 검증했습니다. 이식한 패키지로 기존 실행 서버를 교체하거나 새 PC를 재설치하는 시험은 수행하지 않았습니다. 기기별 드라이버 호환성은 설치 후 확인해야 합니다.

키보드 자동화 경로에서 문자가 중복 입력되는 현상이 원본 환경에서 관찰되었습니다. 이 패키지는 해당 문제를 해결했다고 주장하지 않습니다. 마우스·키보드 입력은 브라우저·자동화 도구·Windows 세션 조합에 따라 별도 확인이 필요합니다.

## 직접 통합 검증

GUI에서 서버를 켠 뒤 다음을 실행합니다.

```powershell
pwsh -NoProfile -File windows/status.ps1
```

성공해야 인증과 PNG 크기를 포함한 `ready` 결과를 보고합니다. 가상 화면 안에 식별 가능한 앱을 배치하고 브라우저에 같은 화면이 보이는지 확인하세요. GUI에서 끄기를 누른 뒤 접속이 종료되는지, 원래 실제 화면과 다른 프로그램은 유지되는지 확인합니다.

## 포인터 오버레이, 창 가드, vscreen (2026-11-06, 같은 PC)

자동 테스트는 순수 로직만 대상으로 합니다. 아래는 실제 화면에서 확인한 내용입니다.

- 브라우저 스트림 위에서 마우스를 움직이면 OS 커서가 가상 모니터 좌표(예: 4800,540)로 옮겨지는 것을 확인했습니다. 이것이 실제 모니터에서 포인터가 사라지는 원인입니다.
- 오버레이를 켜고 가상 화면을 다른 캡처 경로(`agent-desktop`)와 브라우저 스트림 양쪽에서 확인했을 때 포인터와 휠 배지가 나타났습니다. 클릭 이벤트가 훅에 도달하는 것은 디버그 로그로 확인했고, 클릭 물결 자체는 캡처 시점 문제로 화면에서 직접 확인하지 못했습니다(그림은 스프라이트 미리보기로 확인).
- 창 가드: 가상 모니터에서 입력한 직후 켠 `winver`는 가상 모니터로 이동했고, 실제 모니터에서 입력한 직후 켠 `winver`와 가드 시작 전부터 있던 브라우저 창은 이동하지 않았습니다. 초기 구현은 포커스 변경 이벤트까지 감시해서 기존 브라우저 창을 가상 모니터로 옮기는 오류가 있었고, 이를 고쳤습니다.
- `vscreen`: 계산기를 가상 모니터에서 열고 클릭, 타이핑(`12+30`), Enter, 대기, 캡처, 종료까지 확인했습니다(결과 42). 입력 전후 실제 커서 위치는 같았습니다. 한글 입력은 이 시험에서 확인하지 않았습니다.
- 측정: Voxl `GET /screenshot` 약 22 ms(1920x1080 PNG), 브라우저 페이지 캡처 약 456 ms, `/wait?idle=300` 약 305 ms.
- 한계: 클릭 물결과 마우스 훅 기반 기능은 로컬 데스크톱 세션이 필요해서 CI에서 검증하지 않습니다. 오랜 시간 실행 시 메모리·CPU 사용은 측정하지 않았습니다.
